表与字段手册：换个名字也认得出

考试的表名一定和你背的不一样。别背表名，背「角色」和「语义」——任何命名都能对上。

一、只有三种表角色（这是核心）

不管题目叫 Orders、dd、T_Order 还是 销售单，任何 ERP 库里的表都逃不出这三类：

① 业务主表（一行一笔业务） 订单、出库单、入库单、凭证、合同——每条记录就是一次业务动作。
Orders / SaleOrder / T_Bill / dd（订单）/ CK（出库）
② 明细表（一行一个商品） 一张单据有几个商品就有几行，靠「主表Id」挂在主表下面。
OrderDetail / BillDetail / T_BillDetail / mx（明细）
③ 字典表 / 主数据表（提供名字） 客户、产品、员工、仓库、部门——被上面两类表引用，只提供名称和属性。
Customer / Product / Employee / kh（客户）/ sp（商品）

角色之间的两条关系（永远是这两条）

// 明细表 → 主表：靠 主表Id ON 明细.BillId = 主表.Id // 主表 → 字典表：靠 字典Id ON 客户.Id = 主表.CustomerId
记住这一句，题型全能对上：题目给了什么表，先判断它是「主表 / 明细 / 字典」中的哪一类，再套对应句型——主表+明细 → 套打；主表+字典 → JOIN；只给主表 → 单表或分组。

三、命名规律：三种常见风格

风格长什么样你怎么认
英文全称Orders Customer OrderDetail最好认，看词就知道
前缀 + 英文T_Order tbl_Customer B_Order前缀只是「表」的意思，看后半段
拼音首字母dd（订单）mx（明细）kh（客户）sp（商品）国内老系统常见：把拼音读出来
考场技巧：题目通常会附一段「表结构说明」。看不懂名字时，就找三样东西——① 哪个字段像主键（Id/Code/No）② 哪个字段像外键（以别的表名开头，如 CustomerId）③ 哪个字段是金额/数量/时间（Amount/Qty/Date）。找到这三样，90% 的题就能下笔。

五、拿到题目的 30 秒读题法

  1. 圈出「要显示什么」——决定 SELECT 哪几列，也决定要不要连表（跨表字段 → 必须 JOIN）。
  2. 圈出「限定条件」——时间/状态/金额阈值，决定 WHERE。
  3. 圈出「要不要合计」——出现「总共/几单/合计」→ GROUP BY；「超过 X」→ HAVING。
  4. 圈出「所有 / 没有 / 每个…最高」——这几个词直接决定 LEFT JOIN 或 ROW_NUMBER。
  5. 最后看排序要求——ORDER BY，注意行号/时间/金额从大到小。
万一某个字段名实在看不懂：按语义猜一个最像的写上去，并在 SQL 上方写一行注释，例如
-- 假设 Je 是金额字段
手写卷按思路给分，写注释比空着强得多。
三个一定不能猜的东西：① 主键和外键的关系（猜错整题错）；② WHERE 和 HAVING 的位置（放错直接语法错误）；③ LEFT JOIN 的方向（写反数据就少一半）。这三个必须从表结构里确认，不能凭感觉。
