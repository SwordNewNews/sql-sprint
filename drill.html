从零讲明白：SQL 到底在干什么

你现在什么都不会也没关系，这一屏只要 5 分钟。

一、数据库 = 一堆 Excel 表

一个表就是一张 Excel：一行是一条记录（一笔业务），一列是一个字段（一个属性）。

ERP 里一定有两张表：客户表 Customer、订单表 Orders。

订单表里不存客户名字，只存客户编号 CustomerId——因为名字改一次要改一万条订单，太蠢。这就是「关系」。

二、SQL = 对表说的一句人话

任何查询都在回答四件事，对应四个关键字：

SELECT  我要哪几列      ← 挑列
FROM    从哪张表        ← 挑表
WHERE   只要哪些行      ← 挑行
ORDER BY 怎么排序      ← 排队

就这么四句。SELECT * FROM Customer 意思是「客户表所有列、所有行」。先会这个，就入门了。

三、为什么要 JOIN

报表要显示「甲公司 买了 1200」：名字在客户表，金额在订单表。两张表要合起来看 → 用 JOIN。

合起来的粘合剂就是编号：ON 客户.Id = 订单.CustomerId。

一句话记住：JOIN 就是把两张表按编号对齐，对齐的才拼成一行。

四、为什么要 GROUP BY

订单表是「一行一笔」，但报表要「一行一个客户，显示他总共买了多少」——把多行压成一行，这就是分组。

压的时候要算合计，所以有 SUM() COUNT() AVG() 这些「聚合函数」。

铁律：用了聚合函数，SELECT 里没被聚合的列必须写进 GROUP BY，否则报错。

五、增删改：改数据的三个动词

INSERT INTO 表 (列…) VALUES (值…)   -- 加
UPDATE 表 SET 列=值 WHERE 条件       -- 改
DELETE FROM 表 WHERE 条件        -- 删

WHERE 决定改哪几行。忘了写 = 全表遭殃。

讲完了。你现在知道了：挑表 → 挑行 → 挑列 → 排 → （需要合计就分组）→ （需要合表就 JOIN）。
