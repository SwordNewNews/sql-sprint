SQL 课堂：一节课讲透一个概念

第 1 课

单表查询：其实就是在 Excel 里点筛选

场景老板走过来：「把 11 月金额超过 2000 的订单给我列出来，从大到小。」

如果没学过 SQL你会打开 Excel，点金额那一列的筛选箭头，输 2000，再点日期筛选，最后点排序。SQL 就是把你这套鼠标动作写成一句话。

老师带你写四步，一一对应你刚才的鼠标动作：

SELECT OrderNo, Amount, OrderDate   ← 要哪几列（拖选列）
FROM Orders                          ← 哪张表（打开哪个文件）
WHERE Amount > 2000
  AND OrderDate >= '2026-11-01'
  AND OrderDate < '2026-12-01'       ← 筛选行
ORDER BY Amount DESC;              ← 排序，DESC = 从大到小

什么时候用题目里只出现一张表，动词是「查询 / 列出 / 显示 / 找出」。看到这种题别想复杂了，就是它。

怎么记口诀 「选表筛排」：挑列 → 挑表 → 筛行 → 排序。
就像点外卖：要哪几样（SELECT）、哪家店（FROM）、哪些不要（WHERE）、按价格排一下（ORDER BY）。

老师提醒日期区间写 >= 月初 AND < 下月初，不要写 BETWEEN 1号 AND 30号——如果字段带时分秒，30 号当天下午的数据会被漏掉。

第 2 课

JOIN：把两张表按编号「钉」在一起

场景老板要：「订单号 和 客户名字 给我列出来。」
但订单表里只有 CustomerId = 1，没有名字。

为什么分开存一个客户下 100 单，如果每张订单都存一遍名字，客户改名就要改 100 处，迟早改漏。所以名字只存一份在客户表，订单表只存编号——这叫「关系」。

老师带你写把两张表当成两张纸，拿订书机按编号钉起来：

SELECT o.OrderNo, c.CustomerName, o.Amount
FROM Orders o                            ← 第一张纸，起名 o
JOIN Customer c                          ← 第二张纸，起名 c
  ON c.Id = o.CustomerId;               ← 订书机：按编号对齐

读法：「客户的 Id 等于订单里的 CustomerId」。这一行是整道题的灵魂，写对它，一半分到手。

什么时候用题目要显示的字段分散在两张表里（订单号在 A 表、客户名在 B 表）。

怎么记口诀 「连表靠 ON」。
记法像查字典：订单上写着「客户 1 号」，你去客户表翻到 1 号，把名字抄过来。

老师提醒两张表都有 Id 列，所以必须起别名（o. c.），字段前面也带上。不起别名不是不能跑，是阅卷老师看不懂、你自己也会写混。

第 3 课

LEFT JOIN：为什么「没交作业的人」最难写

场景老板要：「每个客户下了几单？没下过单的也要列出来，显示 0。」

难点在哪用上一课的 JOIN，只有「下过单」的客户能匹配上；没下单的客户会被直接扔掉——正好是老板特别要的那部分人。这就像老师点名：只点交作业的人，缺交的人反而消失了。

老师带你写把客户表放左边，让它必须全在，右边没有就补空：

SELECT c.CustomerName, COUNT(o.Id) AS 订单数
FROM Customer c
LEFT JOIN Orders o ON o.CustomerId = c.Id
GROUP BY c.CustomerName;

为什么是 COUNT(o.Id) 而不是 COUNT(*)？因为没下单的客户，右边整行是空的，COUNT(*) 会把这行空记录也数成 1；COUNT(o.Id) 不数空值，结果才是 0。

什么时候用题目出现这些词：「所有」「每个…都」「没有…的」「从未…」「含无明细的」——闭眼 LEFT JOIN。

怎么记口诀 「左连数 0」：左表全保留 + 数右表主键 + 结果是 0。
类比：点名册。左边是全班名单，右边是交作业的人，没交的人名字还在，只是后面写 0。

老师提醒方向写反（把 Orders 放左边）就前功尽弃。想一句：谁「必须全部出现」，谁就放左边。

第 4 课

GROUP BY：把小票按客户装进信封

场景老板要：「每个客户总共花了多少钱？超过 1 万的才给我。」

难点在哪订单表是一行一笔，一个客户有好几行。老板要的是一行一个客户——这是一次「压缩」。

老师带你写想象把每张小票按客户名装进不同信封，然后每个信封算总额：

SELECT c.CustomerName, SUM(o.Amount) AS 总金额
FROM Orders o
JOIN Customer c ON c.Id = o.CustomerId
WHERE o.OrderDate >= '2026-01-01'        ← 先筛小票
GROUP BY c.CustomerName                    ← 再按客户装信封
HAVING SUM(o.Amount) > 10000            ← 最后筛信封
ORDER BY SUM(o.Amount) DESC;

什么时候用题目出现「总共 / 合计 / 几单 / 平均 / 最多」这类「要算数」的词，就是分组统计。

怎么记口诀 「分组 HAVING」，顺序是 先筛小票（WHERE）→ 再装信封（GROUP BY）→ 最后筛信封（HAVING）。
一句话分清：WHERE 筛「票」，HAVING 筛「信封」。

老师提醒最狠的丢分点：SELECT 里的列没被聚合、又不在 GROUP BY 里，直接报错。你只要记住：SELECT 里出现的每一列，问自己「它在 GROUP BY 里吗？被 SUM/COUNT 包了吗？」

第 5 课

每组取第一：先排名，再取第 1 名

场景老板要：「每个客户金额最高的那一单是哪个？」

难点在哪这是「每个班里考第一的人是谁」。你不能简单地按金额排序取第一条——那只是全校第一。必须在每个班内部排名。

老师带你写两步：先给每行发一个「班内名次」，再只要名次 1 的：

SELECT * FROM (
  SELECT o.*,
         ROW_NUMBER() OVER (
           PARTITION BY o.CustomerId      ← 按客户分班
           ORDER BY o.Amount DESC         ← 班内按金额排名
         ) AS rn
  FROM Orders o
) t
WHERE t.rn = 1;                          ← 只要第 1 名

什么时候用题目出现「每个…最高/最新/最好/第一」。注意是「每个」+「最」，两个词同时出现才算。

怎么记口诀 「编号取 1」：PARTITION BY = 分班，ORDER BY = 班内排名，外面 rn = 1 = 举手。
类比：运动会。先按年级分组，组内排名次，然后每个年级只叫第一名上台。

老师提醒如果你实在记不住 ROW_NUMBER() OVER() 这串，就写子查询版的「金额 = 该客户最大金额」，也能拿大部分分。不会先进函数，先用笨办法，别空白。

第 6 课

关联更新：照着价目表批量改小票

场景产品涨价了。老板要：「把未审核订单的金额，按产品表的最新单价重算一遍。」

难点在哪你不能一条条手改（几千单）。要「照着价目表批量改」——这就是用另一张表的数据去更新这张表。

老师带你写SQL Server 的招牌写法：别名写在 UPDATE 后面，表在 FROM 里连：

UPDATE o                                  ← 要改哪张表的别名
SET o.Amount = o.Qty * p.Price           ← 改成什么
FROM Orders o
JOIN Product p ON p.Id = o.ProductId    ← 价目表从哪来
WHERE o.Status = 0;                      ← 只改哪些行

什么时候用题目出现「按…重算 / 根据…更新 / 批量修改」，而且数据来源在另一张表。
单表改数不用 FROM——UPDATE 表 SET 列=值 WHERE 条件 就行。

怎么记口诀 「UPDATE 别名」。
类比：照价目表改小票。手里拿着价目表（Product），一张张对订单（Orders），把金额划掉重写。

老师提醒删除也是同一个套路：DELETE o FROM Orders o JOIN Customer c ON … WHERE c.Status = 9。改和删的形状一样，只是第一个词不同。

第 7 课

事务：转账为什么必须「一起成功」

场景把 A 账户的 100 元转给 B 账户。

难点在哪如果「A 扣 100」执行完，程序崩了，「B 加 100」没执行——钱凭空消失。所以这两步必须捆成一件事：要么都成，要么都不做。

老师带你写

BEGIN TRAN;                              ← 开一个事务
UPDATE Account SET Balance = Balance - 100 WHERE Id = 1;
UPDATE Account SET Balance = Balance + 100 WHERE Id = 2;
COMMIT TRAN;                              ← 确认（出错就 ROLLBACK TRAN 撤销）

什么时候用题目出现「转账 / 保证同时成功 / 要么都成功要么都不生效 / 回滚」。

怎么记口诀 「BEGIN COMMIT」，三个词：开（BEGIN）、成（COMMIT）、撤（ROLLBACK）。
类比：撕不开的连体单据——要么两张一起生效，要么一起作废。

老师提醒这三个关键字写出来就是分。哪怕两条 UPDATE 写得不完美，只要 BEGIN / COMMIT / ROLLBACK 都在，概念分基本能拿到。

第 8 课

套打：一张单据为什么要连两张表

场景仓库要打一张出库单：上面是单号、日期、客户，下面列着这一单的所有商品。

难点在哪单据信息存在两张表：BillMaster（表头，1 行）和 BillDetail（明细，N 行）。打印时要一次把两张表的数据都取出来，按明细行号排好——这叫「主从表」。

老师带你写

SELECT m.BillNo, m.BillDate, d.LineNo, d.ProductName, d.Qty
FROM BillMaster m
LEFT JOIN BillDetail d ON d.BillId = m.Id
WHERE m.BillNo = 'CK20261126001'
ORDER BY d.LineNo;                    ← 按明细行号排，打印才对得上

什么时候用题目出现「单据 / 打印 / 表头 + 明细 / 出库单 / 发票」。

怎么记口诀 「套打左连明细」。
类比：一张表单，上面填一遍，下面能填很多行。表头只有一个，明细可以很多行，甚至零行。

老师提醒必须 LEFT JOIN。因为「没有明细的单据」也要打印（比如退单、草稿单），用 INNER JOIN 会把这些单据整张弄丢。这是套打题最典型的判分点。
