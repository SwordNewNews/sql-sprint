SQL Server 手写笔试 · 突击清单

考试明天（周五）下午现场手写，范围：多表增删改查 ／ 自定义报表 ／ 套打。手写考套路，不考记忆量——把下面 5 个骨架默写熟，多数题都能套。

先记这一条：写 SQL 的顺序和读 SQL 的顺序相反。
写的时候永远按这个顺序落笔，就不会漏条件：
SELECT … FROM … JOIN … ON … WHERE … GROUP BY … HAVING … ORDER BY …

一、多表查询骨架（最高频）

1. 两种连接，只背这两个

-- 内连接：两边都有的数据才出来
SELECT o.OrderNo, c.CustomerName, o.Amount
FROM Orders o
JOIN Customer c ON c.Id = o.CustomerId;

-- 左连接：左边全要，右边没有就补 NULL（报表/套打常用）
SELECT o.OrderNo, c.CustomerName, o.Amount
FROM Orders o
LEFT JOIN Customer c ON c.Id = o.CustomerId;
手写时把 ON 条件写全 = 拿一半分。多表就一路 JOIN … ON … 叠下去，别名一定要写（o. c.），否则阅卷老师看不出你想连哪张表。

2. 三种筛选条件的位置（最容易错）

条件类型写在哪例子
过滤行（原始数据）WHEREWHERE o.Amount > 1000
过滤分组后的结果HAVINGHAVING SUM(o.Amount) > 10000
左连接后“只要没匹配上的”WHERE 右表.主键 IS NULLWHERE c.Id IS NULL（找没下过单的客户）

二、增删改（含 ERP 常见的批量写法）

-- 插入一行
INSERT INTO Customer (CustomerName, Phone, CreateTime)
VALUES (N'张三', '13800000000', GETDATE());

-- 插入查询结果（批量导入/结转）
INSERT INTO OrderLog (OrderId, Action, CreateTime)
SELECT o.Id, N'结转', GETDATE()
FROM Orders o
WHERE o.Status = 1;

-- 带条件的更新
UPDATE Orders
SET Status = 2, UpdateTime = GETDATE()
WHERE Id = 1001;

-- ★ 关联更新（ERP 里改价、改库存必考）
UPDATE o
SET o.Amount = o.Qty * p.Price
FROM Orders o
JOIN Product p ON p.Id = o.ProductId
WHERE o.Status = 0;

-- ★ 关联删除
DELETE o
FROM Orders o
JOIN Customer c ON c.Id = o.CustomerId
WHERE c.Status = 9;

-- 事务：要么全成功，要么全回滚
BEGIN TRAN;
UPDATE Account SET Balance = Balance - 100 WHERE Id = 1;
UPDATE Account SET Balance = Balance + 100 WHERE Id = 2;
COMMIT TRAN;
-- 出错时用 ROLLBACK TRAN;
UPDATE o SET … FROM Orders o JOIN … 这种「别名写在 UPDATE 上」是 T-SQL 独有写法，正好是 SQL Server 实施岗的常见考点，务必记住：UPDATE 后面跟别名，FROM 后面再把表连起来。

三、自定义报表（四件套）

1. 分组统计

SELECT c.CustomerName,
       COUNT(o.Id)        AS 订单数,
       SUM(o.Amount)      AS 总金额,
       AVG(o.Amount)      AS 平均金额,
       MAX(o.OrderDate)   AS 最近下单
FROM Orders o
JOIN Customer c ON c.Id = o.CustomerId
WHERE o.OrderDate >= '2026-01-01'
GROUP BY c.CustomerName
HAVING SUM(o.Amount) > 10000
ORDER BY 总金额 DESC;
背死这句规则：SELECT 里出现的列，要么在 GROUP BY 里，要么被聚合函数包住。手写时先把 GROUP BY 写好，再回头补 SELECT。

2. 分段统计（CASE WHEN）

SELECT
  SUM(CASE WHEN Amount < 1000 THEN 1 ELSE 0 END)          AS 小额单数,
  SUM(CASE WHEN Amount BETWEEN 1000 AND 5000 THEN 1 ELSE 0 END) AS 中额单数,
  SUM(CASE WHEN Amount > 5000 THEN 1 ELSE 0 END)          AS 大额单数
FROM Orders;

3. 排名 / 取每组前 N 条（窗口函数）

-- 每个客户金额最高的那一单
SELECT * FROM (
  SELECT o.*, c.CustomerName,
         ROW_NUMBER() OVER (PARTITION BY o.CustomerId ORDER BY o.Amount DESC) AS rn
  FROM Orders o JOIN Customer c ON c.Id = o.CustomerId
) t
WHERE t.rn = 1;

4. 子查询 / EXISTS（“没有”“存在”类问题）

-- 没下过单的客户（两种写法都对，考试写一种即可）
SELECT * FROM Customer c
WHERE NOT EXISTS (SELECT 1 FROM Orders o WHERE o.CustomerId = c.Id);

SELECT * FROM Customer
WHERE Id NOT IN (SELECT CustomerId FROM Orders WHERE CustomerId IS NOT NULL);

四、套打（单据取数）

「套打」在 ERP 里是把数据填到预印好的单据纸上（凭证、发票、出库单）。SQL 层面考的不是排版，而是取数：一张单据 = 主表 1 行 + 明细 N 行，要一次查全并排好序。

1. 主表 + 明细一次取出（左连接，主表必须全量）

SELECT m.BillNo, m.BillDate, m.CustomerName, m.TotalAmount,
       d.LineNo, d.ProductName, d.Qty, d.Price, d.Amount
FROM BillMaster m
LEFT JOIN BillDetail d ON d.BillId = m.Id
WHERE m.BillNo = 'CK20261126001'
ORDER BY d.LineNo;
为什么必须 LEFT JOIN：没有明细的单据也要打出来（显示空白行）。用 INNER JOIN 会把这类单据整张丢掉——这是“套打”场景最典型的判分点。

2. 把多行明细拼成一行（经典：FOR XML PATH）

-- 一张单据一行，明细用逗号拼起来：套打模板常用
SELECT m.BillNo,
       STUFF((
         SELECT ',' + d.ProductName + '×' + CAST(d.Qty AS VARCHAR(10))
         FROM BillDetail d
         WHERE d.BillId = m.Id
         ORDER BY d.LineNo
         FOR XML PATH(''), TYPE
       ).value('.', 'NVARCHAR(MAX)'), 1, 1, '') AS 明细
FROM BillMaster m;

这串长得吓人，但结构固定：STUFF((子查询拼串 FOR XML PATH('')),1,1,'')。记不住全部就写 + ',' 拼串的部分，也比空着强。

3. 单据统计（表头合计）

SELECT m.BillNo, m.BillDate, m.CustomerName,
       COUNT(d.Id)   AS 明细行数,
       SUM(d.Qty)    AS 总数量,
       SUM(d.Amount) AS 总金额
FROM BillMaster m
LEFT JOIN BillDetail d ON d.BillId = m.Id
WHERE m.BillDate >= '2026-11-01' AND m.BillDate < '2026-12-01'
GROUP BY m.BillNo, m.BillDate, m.CustomerName
ORDER BY m.BillNo;

五、SQL Server 语法注意（专坑手写）

要做的事写法
取前 N 行SELECT TOP 10 * FROM Orders ORDER BY Amount DESC
字符串拼接c.LastName + c.FirstName（数字要先 CAST(x AS VARCHAR)）
空值替换ISNULL(Amount, 0)（T-SQL 专有，别写 IFNULL）
当前时间GETDATE()（不是 NOW()）
日期格式化CONVERT(VARCHAR(10), BillDate, 120) → 2026-11-26
日期加减DATEADD(DAY, -7, GETDATE())、DATEDIFF(DAY, a, b)
中文字符串前面加 N：N'张三'
表名/列名是关键字用方括号：[Order]、[User]
不等于<>（写 != 也认）
判断空值IS NULL / IS NOT NULL，不能写 = NULL
字符串转数字CAST(Col AS INT) 或 CONVERT(INT, Col)
三个最常见的丢分点：
① = NULL（错）→ 必须 IS NULL；
② SELECT 里有列没进 GROUP BY 也没聚合（错）；
③ WHERE 里用聚合函数（错）→ 聚合条件放 HAVING。

六、预测题（先自己写，再点开答案）

1. 查询 2026 年每个客户的下单总数与总金额，只保留总金额超过 1 万元的，按总金额从高到低排序。

参考答案
SELECT c.CustomerName, COUNT(o.Id) AS 订单数, SUM(o.Amount) AS 总金额
FROM Orders o
JOIN Customer c ON c.Id = o.CustomerId
WHERE o.OrderDate >= '2026-01-01' AND o.OrderDate < '2027-01-01'
GROUP BY c.CustomerName
HAVING SUM(o.Amount) > 10000
ORDER BY SUM(o.Amount) DESC;

2. 查出没有任何订单的客户。

参考答案
SELECT c.*
FROM Customer c
WHERE NOT EXISTS (SELECT 1 FROM Orders o WHERE o.CustomerId = c.Id);

等价写法：LEFT JOIN Orders o ON o.CustomerId=c.Id WHERE o.Id IS NULL。

3. 每个客户金额最高的那一笔订单（只要一条）。

参考答案
SELECT * FROM (
  SELECT o.*, ROW_NUMBER() OVER (PARTITION BY o.CustomerId ORDER BY o.Amount DESC) AS rn
  FROM Orders o
) t
WHERE t.rn = 1;

4. 把订单按金额分成三段（0–999 / 1000–4999 / 5000 以上），统计各段的订单数量。

参考答案
SELECT
  SUM(CASE WHEN Amount < 1000 THEN 1 ELSE 0 END) AS 小额,
  SUM(CASE WHEN Amount >= 1000 AND Amount < 5000 THEN 1 ELSE 0 END) AS 中额,
  SUM(CASE WHEN Amount >= 5000 THEN 1 ELSE 0 END) AS 大额
FROM Orders;

也可以 GROUP BY 一个 CASE 表达式，两种都给分。

5. 用订单明细表，把每张单据的商品名拼成一行，用逗号分隔。

参考答案
SELECT m.BillNo,
       STUFF((SELECT ',' + d.ProductName
              FROM BillDetail d
              WHERE d.BillId = m.Id
              ORDER BY d.LineNo
              FOR XML PATH(''), TYPE).value('.', 'NVARCHAR(MAX)'), 1, 1, '') AS 商品清单
FROM BillMaster m;

6. 把产品表的单价上调 5%，只调分类为「电子」的产品，并记录修改时间。

参考答案
UPDATE Product
SET Price = Price * 1.05, UpdateTime = GETDATE()
WHERE Category = N'电子';

7. 库存表按「产品 + 仓库」关联更新：把本月入库数量累加到库存。

参考答案
UPDATE s
SET s.Qty = s.Qty + i.InQty, s.UpdateTime = GETDATE()
FROM Stock s
JOIN Inbound i ON i.ProductId = s.ProductId AND i.WarehouseId = s.WarehouseId
WHERE i.InDate >= '2026-11-01';

8. 删除重复数据，同一手机号只保留 Id 最小的那条。

参考答案
DELETE t FROM (
  SELECT *, ROW_NUMBER() OVER (PARTITION BY Phone ORDER BY Id) AS rn
  FROM Customer
) t
WHERE t.rn > 1;

9. 按月份统计销售额，并把 1–12 月转成 12 列（行转列）。

参考答案
SELECT CustomerId,
  SUM(CASE WHEN MONTH(OrderDate)=1  THEN Amount ELSE 0 END) AS M1,
  SUM(CASE WHEN MONTH(OrderDate)=2  THEN Amount ELSE 0 END) AS M2,
  -- … 3 到 11 月同样写法 …
  SUM(CASE WHEN MONTH(OrderDate)=12 THEN Amount ELSE 0 END) AS M12
FROM Orders
WHERE YEAR(OrderDate) = 2026
GROUP BY CustomerId;

时间够可以补 PIVOT 写法，不够就用上面这种 CASE 行转列，一样得分。

10. 查询每张出库单的表头信息 + 明细行，没有明细的也要显示。

参考答案
SELECT m.BillNo, m.BillDate, m.CustomerName,
       d.LineNo, d.ProductName, d.Qty, d.Amount
FROM BillMaster m
LEFT JOIN BillDetail d ON d.BillId = m.Id
WHERE m.BillType = N'出库'
ORDER BY m.BillNo, d.LineNo;

11. 分页：查订单表第 3 页，每页 20 条，按下单时间倒序。

参考答案
SELECT *
FROM Orders
ORDER BY OrderDate DESC
OFFSET 40 ROWS FETCH NEXT 20 ROWS ONLY;

旧写法也行：SELECT TOP 20 * FROM (SELECT TOP 60 * FROM Orders ORDER BY OrderDate DESC) t ORDER BY OrderDate。

12. 转账：A 账户扣 100 给 B，保证要么都成功要么都不生效。

参考答案
BEGIN TRAN;
UPDATE Account SET Balance = Balance - 100 WHERE Id = 1;
UPDATE Account SET Balance = Balance + 100 WHERE Id = 2;
IF @@ERROR <> 0
  ROLLBACK TRAN;
ELSE
  COMMIT TRAN;

能写出 BEGIN TRAN / COMMIT / ROLLBACK 三个关键字就是得分点。

七、明天临场清单

  1. 先写 FROM … JOIN … ON，把表连对；再补 WHERE；有聚合就写 GROUP BY；最后回头写 SELECT。这一步顺序能救回大量分数。
  2. 每张表都起别名，字段前带别名前缀，阅卷老师一眼能看懂。
  3. 不确定的函数就换通用的：不确定 FORMAT() 就用 CONVERT()；不确定窗口函数就写子查询。宁可笨但正确。
  4. 不会就写思路注释：-- 思路：先按客户分组求合计，再筛 >10000。手写卷子给分看思路，不只看完整度。
  5. 多表题必检查：是否该用 LEFT JOIN（主表全量）、是否有 IS NULL、聚合条件是否错放 WHERE。
  6. 写完从 FROM 往回读一遍：编号、括号、逗号、END、分号，手写最容易漏。
