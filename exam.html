1

查询 2026 年 11 月下单、且金额大于 2000 的订单，显示订单号、金额、下单日期，按金额从高到低排列。

10 分单表查询★★
▶查看解析选表筛排 
SELECT OrderNo, Amount, OrderDate
FROM Orders
WHERE Amount > 2000
  AND OrderDate >= '2026-11-01'
  AND OrderDate < '2026-12-01'
ORDER BY Amount DESC;
  1. SELECT 挑列：只取题目要的三列，不要写 *。
  2. WHERE 筛行：两个条件用 AND 连。日期用「≥ 月初 且 < 下月初」，比 BETWEEN 1号 AND 30号 稳。
  3. ORDER BY 排序：DESC 是从大到小，不写就是从小到大。
日期区间 5 分排序 3 分字段 2 分
最易踩的坑：写 OrderDate = '2026-11' 或 LIKE '2026-11%'。字段是日期型时，前者查不到任何数据，后者可能因格式不符失败。

查询每笔订单的订单号、客户名称、订单金额（订单表只存客户编号，客户名称在客户表）。

10 分两表连接★★
▶查看解析连表靠 ON 
SELECT o.OrderNo, c.CustomerName, o.Amount
FROM Orders o
JOIN Customer c ON c.Id = o.CustomerId;
  1. 起别名：两张表都有 Id，不起别名就写不清谁是谁。
  2. ON 是灵魂：c.Id = o.CustomerId——客户表的主键 = 订单表里的外键。
  3. 字段带前缀：o.OrderNo、c.CustomerName，阅卷一眼看懂。
ON 条件 5 分别名 3 分字段 2 分
最易踩的坑：把连接条件写进 WHERE（旧写法也对，但可读性差）；或者 ON c.Id = o.Id——两边都写 Id 就变成按订单号连客户，结果全错。
3

统计每个客户的订单数量，没有下过单的客户也要显示，数量为 0。

12 分LEFT JOIN★★★
▶查看解析左连数 0 
SELECT c.CustomerName, COUNT(o.Id) AS 订单数
FROM Customer c
LEFT JOIN Orders o ON o.CustomerId = c.Id
GROUP BY c.CustomerName;
  1. 谁全量谁在左：客户要全部出现，所以 Customer 放左边、用 LEFT JOIN。
  2. COUNT 要数右表主键：没下单的客户右表整行是空，COUNT(o.Id) 不数空值 → 得到 0；COUNT(*) 会把空行数成 1。
  3. GROUP BY：用了聚合，就要按客户名分组。
LEFT JOIN 7 分COUNT(o.Id) 5 分
最易踩的坑：用 JOIN（内连接）——没下单的客户整行被扔掉，正好是题目要的那部分人，直接丢 7 分。
4

产品价格调整后，把「未审核」（Status = 0）订单的金额重算为：数量 × 产品表当前单价。

8 分关联更新★★★
▶查看解析UPDATE 别名 
UPDATE o
SET o.Amount = o.Qty * p.Price
FROM Orders o
JOIN Product p ON p.Id = o.ProductId
WHERE o.Status = 0;
  1. UPDATE 后面跟别名：这是 SQL Server 的招牌写法，改的是 o 这张表。
  2. SET 里能引用另一张表：p.Price 来自 JOIN 进来的产品表。
  3. WHERE 限定范围：只改未审核的，别把历史单据一起改了。
UPDATE 别名 3 分FROM/JOIN 3 分SET 表达式 2 分
最易踩的坑：写成 UPDATE Orders SET Amount = Qty * Price——订单表里没有 Price 这个列，直接报错。

二、自定义报表

30 分
5

统计 2026 年每个客户的下单次数与总金额，只保留总金额超过 10000 的客户，按总金额从高到低排列。

10 分GROUP BY + HAVING★★★
▶查看解析分组 HAVING 
SELECT c.CustomerName,
       COUNT(o.Id) AS 下单次数,
       SUM(o.Amount) AS 总金额
FROM Orders o
JOIN Customer c ON c.Id = o.CustomerId
WHERE o.OrderDate >= '2026-01-01'
  AND o.OrderDate < '2027-01-01'
GROUP BY c.CustomerName
HAVING SUM(o.Amount) > 10000
ORDER BY SUM(o.Amount) DESC;
  1. 先筛行再分组：时间范围属于「行」，写 WHERE。
  2. 总额超 1 万属于「组」：写 HAVING，因为此时已有分组结果。
  3. SELECT 的列要么分组要么聚合：客户名在 GROUP BY 里，两个数字被 COUNT/SUM 包住，全部合法。
分组 4 分WHERE 3 分HAVING 3 分
最易踩的坑：把 SUM(o.Amount) > 10000 写进 WHERE——聚合函数不能出现在 WHERE，直接语法错误。
6

按客户统计 1–12 月各月的订单金额，做成「一行一个客户、12 列一个月」的横向报表。

10 分行转列★★★
▶查看解析SUM(CASE WHEN …) 
SELECT c.CustomerName,
  SUM(CASE WHEN MONTH(o.OrderDate) = 1  THEN o.Amount ELSE 0 END) AS M1,
  SUM(CASE WHEN MONTH(o.OrderDate) = 2  THEN o.Amount ELSE 0 END) AS M2,
  -- …… 3 到 11 月同样写法 ……
  SUM(CASE WHEN MONTH(o.OrderDate) = 12 THEN o.Amount ELSE 0 END) AS M12
FROM Orders o
JOIN Customer c ON c.Id = o.CustomerId
WHERE YEAR(o.OrderDate) = 2026
GROUP BY c.CustomerName;
  1. 行转列的通用套路：SUM(CASE WHEN 条件 THEN 数值 ELSE 0 END)，每个月份写一列。
  2. 不满足条件的行给 0，SUM 才能只累加当月金额。
  3. 写不完 12 列就写 3 列 + 注明「其余月份同理」，判分按结构给。
CASE 结构 5 分列数齐全 3 分分组 2 分
最易踩的坑：用 SUM(o.Amount) 直接按月份分组——那样出来是 12 行（纵向），题目要的是 12 列（横向）。
7

查询每个客户金额最高的那一笔订单（显示客户名、订单号、金额）。

10 分ROW_NUMBER★★★
▶查看解析编号取 1 
SELECT t.CustomerName, t.OrderNo, t.Amount FROM (
  SELECT c.CustomerName, o.OrderNo, o.Amount,
         ROW_NUMBER() OVER (
           PARTITION BY o.CustomerId
           ORDER BY o.Amount DESC
         ) AS rn
  FROM Orders o
  JOIN Customer c ON c.Id = o.CustomerId
) t
WHERE t.rn = 1;
  1. PARTITION BY = 按客户分班，ORDER BY = 班内按金额排队。
  2. 外面套一层再筛：窗口函数不能在同一个 SELECT 的 WHERE 里直接过滤，必须包成子查询。
  3. 不会窗口函数就用子查询版（金额 = 该客户最大金额），也能拿大部分分。
窗口函数 5 分外层次查询 3 分rn = 1 2 分
最易踩的坑：SELECT MAX(Amount) FROM Orders GROUP BY CustomerId 只能拿到金额，拿不到对应的订单号和其他字段。

三、套打取数

8

打印单据号 CK20261126001 的出库单：显示单号、日期、客户、明细行号、商品名称、数量，按明细行号排序。

10 分套打★★
▶查看解析套打左连明细 
SELECT m.BillNo, m.BillDate, m.CustomerName,
       d.LineNo, d.ProductName, d.Qty
FROM BillMaster m
LEFT JOIN BillDetail d ON d.BillId = m.Id
WHERE m.BillNo = 'CK20261126001'
ORDER BY d.LineNo;
  1. 主表 1 行 + 明细 N 行：用 BillId 关联，一次查全。
  2. 必须 ORDER BY 行号：打印是按行号往下排的，不排序会乱。
  3. 用 LEFT JOIN 更稳：即使这张单据明细缺失，也能打出表头。
LEFT JOIN 5 分条件 3 分排序 2 分
最易踩的坑：忘了 ORDER BY d.LineNo。数据能出来，但打印顺序乱，等于不能用。
9

查询所有出库单的单号、日期、客户、明细行号、商品、数量，没有明细的单据也要显示。

10 分LEFT JOIN 判分点★★★
▶查看解析本题只考一件事 
SELECT m.BillNo, m.BillDate, m.CustomerName,
       d.LineNo, d.ProductName, d.Qty
FROM BillMaster m
LEFT JOIN BillDetail d ON d.BillId = m.Id
WHERE m.BillType = N'出库'
ORDER BY m.BillNo, d.LineNo;
  1. 「没有明细也要显示」= 主表全量，所以 BillMaster 在左、用 LEFT JOIN。
  2. 类型条件：BillType = N'出库'，中文加 N 防乱码。
  3. 双重排序：先按单号，再按行号，同一张单据的明细才连在一起。
LEFT JOIN 9 分条件 1 分
最易踩的坑：写成 JOIN。数据看起来"正常"，但空明细的单据全丢了——这题几乎就是在考你有没有用 LEFT。

四、概念简答

10

简述 WHERE 与 HAVING 的区别；并写出事务的三个关键字。

10 分概念★
▶查看解析最容易拿的分
  1. WHERE 在分组之前筛「原始行」，不能包含聚合函数。
  2. HAVING 在分组之后筛「组」，通常跟 GROUP BY 一起用，可以包含聚合函数。
  3. 事务三关键字：BEGIN TRAN（开始）、COMMIT TRAN（提交）、ROLLBACK TRAN（回滚）。作用是让一组操作要么全部生效、要么全部不生效。
WHERE 定义 3 分HAVING 定义 3 分三关键字 4 分
最易踩的坑：只写「WHERE 在前、HAVING 在后」——这是位置不是区别。要说出「筛行 / 筛组」和「能不能用聚合」。
交卷前 60 秒检查 ① 空值是不是写成了 IS NULL；② 聚合条件有没有错放进 WHERE；③ SELECT 的列是否都在 GROUP BY 或被聚合；④「所有 / 没有」类题目有没有用 LEFT JOIN；⑤ 括号、引号、END、分号是否成对。
