1单表查询选表筛排
场景「把 11 月金额超过 2000 的订单列出来，从大到小。」
老师带你写 
SELECT OrderNo, Amount, OrderDate   ← 要哪几列
FROM Orders                          ← 哪张表
WHERE Amount > 2000
  AND OrderDate >= '2026-11-01'
  AND OrderDate < '2026-12-01'       ← 筛行
ORDER BY Amount DESC;              ← 倒序
就是在 Excel 里点筛选箭头、输条件、点排序——SQL 把鼠标动作写成一句话。
什么时候用题目只涉及一张表，动词是「查询/列出/显示/找出」。
怎么记「选表筛排」：挑列→挑表→筛行→排序。像点外卖：要哪几样、哪家店、哪些不要、按价格排。
老师提醒日期写 >= 月初 AND < 下月初，别用 BETWEEN 1号 AND 30号（会漏掉 30 号下午）。
2JOIN 连表连表靠 ON
场景「订单号 + 客户名字列出来。」但订单表只有 CustomerId，没名字。
为什么分开存名字只存一份，改名只改一处。这就是「关系」。老师带你写 
SELECT o.OrderNo, c.CustomerName, o.Amount
FROM Orders o
JOIN Customer c
  ON c.Id = o.CustomerId;   ← 按编号对齐
读法：「客户的 Id 等于订单里的 CustomerId」。
什么时候用要显示的字段分散在两张表。
怎么记「连表靠 ON」。像查字典：订单上写「客户 1 号」，去客户表翻到 1 号，把名字抄过来。
老师提醒两表都有 Id，必须起别名，字段前带前缀。
3LEFT JOIN左连数 0
场景「每个客户下了几单？没下过单的也要显示 0。」
难点普通 JOIN 只有下过单的能匹配上，没下单的被扔掉——正好是老板要的那部分人。就像点名只点交作业的，缺交的反而消失。老师带你写 
SELECT c.CustomerName, COUNT(o.Id) AS 订单数
FROM Customer c
LEFT JOIN Orders o ON o.CustomerId = c.Id
GROUP BY c.CustomerName;
为什么 COUNT(o.Id) 不是 COUNT(*)：没下单的客户右表是空行，COUNT(*) 会数成 1。
什么时候用出现「所有」「每个…都」「没有…的」「含无明细的」——闭眼 LEFT JOIN。
怎么记「左连数 0」。点名册：全班名单在左边，没交作业的名字还在，后面写 0。
老师提醒方向别反：谁必须全部出现，谁放左边。
4GROUP BY分组 HAVING
场景「每个客户总共花多少？超过 1 万的才要。」
老师带你写把每张小票按客户装进不同信封，再算每个信封的总额： 
SELECT c.CustomerName, SUM(o.Amount) AS 总金额
FROM Orders o
JOIN Customer c ON c.Id = o.CustomerId
WHERE o.OrderDate >= '2026-01-01'   ← 筛小票
GROUP BY c.CustomerName               ← 装信封
HAVING SUM(o.Amount) > 10000      ← 筛信封
ORDER BY SUM(o.Amount) DESC;
什么时候用出现「总共/合计/几单/平均/最多」这类要算数的词。
怎么记「分组 HAVING」：WHERE 筛票，HAVING 筛信封。
老师提醒SELECT 里的列没被聚合、又不在 GROUP BY，报错。写完逐列问自己一遍。
5每组取第一编号取 1
场景「每个客户金额最高的那一单是哪个？」
难点不是全校第一，是每个班第一。先分班排名，再举手。 
SELECT * FROM (
  SELECT o.*, ROW_NUMBER() OVER (
      PARTITION BY o.CustomerId   ← 分班
      ORDER BY o.Amount DESC      ← 班内排名
  ) AS rn
  FROM Orders o
) t
WHERE t.rn = 1;                   ← 举手
什么时候用「每个…最高/最新/最好/第一」——「每个」+「最」同时出现。
怎么记「编号取 1」。运动会：分年级排名次，每个年级只叫第一名上台。
老师提醒记不住这串就写子查询版「金额 = 该客户最大金额」，也能拿大部分分，别空着。
6关联更新UPDATE 别名
场景涨价了，「把未审核订单的金额，按产品表最新单价重算」。
老师带你写别名写在 UPDATE 后面，表在 FROM 里连——SQL Server 招牌写法： 
UPDATE o                          ← 改哪张表
SET o.Amount = o.Qty * p.Price   ← 改成什么
FROM Orders o
JOIN Product p ON p.Id = o.ProductId
WHERE o.Status = 0;              ← 只改哪些行
什么时候用「按…重算/根据…更新/批量修改」，数据来源在另一张表。单表改数不用 FROM。
怎么记「UPDATE 别名」。照价目表改小票：拿价目表一张张对，金额划掉重写。
老师提醒删除同一个套路：DELETE o FROM Orders o JOIN … WHERE …，形状一样，只差第一个词。
7事务BEGIN COMMIT
场景把 A 账户的 100 元转给 B。
难点A 扣完、程序崩了、B 没加上——钱凭空消失。两步必须捆成一件事。 
BEGIN TRAN;
UPDATE Account SET Balance = Balance - 100 WHERE Id = 1;
UPDATE Account SET Balance = Balance + 100 WHERE Id = 2;
COMMIT TRAN;
-- 出错：ROLLBACK TRAN;
什么时候用「转账/保证同时成功/要么都成功要么回滚」。
怎么记「BEGIN COMMIT」：开、成、撤。连体单据，撕不开，要么一起生效要么一起作废。
老师提醒三个关键字写出来就是分，概念分最好拿。
8套打取明细套打左连明细
场景打一张出库单：上面单号日期客户，下面列所有商品。
难点表头 1 行、明细 N 行，两张表一次取全。 
SELECT m.BillNo, m.BillDate, d.LineNo, d.ProductName, d.Qty
FROM BillMaster m
LEFT JOIN BillDetail d ON d.BillId = m.Id
WHERE m.BillNo = 'CK20261126001'
ORDER BY d.LineNo;
什么时候用「单据/打印/表头+明细/出库单/发票」。
怎么记「套打左连明细」。一张表单：上面填一遍，下面能填很多行。
老师提醒必须 LEFT JOIN——没有明细的单据也要打印，用 INNER 会整张弄丢。
